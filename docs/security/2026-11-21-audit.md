## รายละเอียด

**F1 บัญชีฐานข้อมูลของแอปเป็น superuser** — `csis` มี rolsuper/createrole/createdb ถ้ามีช่องโหว่ SQL ใด ๆ ผู้โจมตีจะได้ทั้งเครื่องฐานข้อมูล
แก้: สร้าง `csis_app` (NOSUPERUSER, อ่าน/เขียนข้อมูลเท่านั้น) แอปใช้ `DATABASE_URL`, migrate ใช้ `MIGRATION_DATABASE_URL` (`apps/api/prisma.config.ts`, `scripts/db-app-role.sql`)
ทดสอบซ้ำ: csis_app อ่านข้อมูลได้, `DROP TABLE` / `CREATE TABLE` / `ALTER ROLE ... SUPERUSER` / อ่าน `_prisma_migrations` ถูกปฏิเสธทั้งหมด; API ทดสอบผ่าน 29/29

**F2 คุกกี้ไม่มี Secure** — `COOKIE_SECURE=false` แต่ลิงก์สาธิตเป็น https
แก้: ตั้ง Secure อัตโนมัติเมื่อคำขอมาจากหน้า https (Origin ที่ CSRF ตรวจแล้ว) (`apps/api/src/auth/session.ts`)
ทดสอบซ้ำ: ล็อกอินผ่านลิงก์ https ได้ `HttpOnly; Secure; SameSite=Lax`; ล็อกอินผ่าน http://localhost ยังได้

**F3 CSP/HSTS** — แก้ใน `apps/web/next.config.ts` (เฉพาะ production) · ทดสอบซ้ำ: header มาครบ, หน้าเว็บไม่มี error ของ CSP

**F5 ไลบรารี** — `prisma` CLI (ผ่าน `@prisma/config` → `effect` ReDoS) และ `uuid` ผ่าน `exceljs` · ทั้งสองไม่รับข้อมูลจากผู้ใช้ในเส้นทางที่มีช่องโหว่ · แผน: ย้าย `prisma` ไป devDependencies ตอนตั้งเครื่องจริง และอัปเดตเมื่อมีรุ่นแก้

**F6 รหัสผ่านวันเกิด** — คนที่รู้วันเกิดนักเรียนเข้าบัญชีได้ · มาตรการที่มี: ล็อกบัญชีเมื่อรหัสผิดติดกัน, จำกัด 10 ครั้ง/นาที, บันทึกการล็อกอิน · แนะนำ: เปิด `STUDENT_FORCE_PASSWORD_CHANGE=true` ก่อนใช้จริง

## ที่ตรวจแล้วผ่าน (PASS)

- ไม่มี `.env` หรือรหัสลับใน Git; ฐานข้อมูลและ API ฟังเฉพาะ 127.0.0.1
- รหัสผ่านเก็บแบบ Argon2; ล็อกบัญชีเมื่อผิดซ้ำ; จำกัดอัตราล็อกอิน; ตอบเวลาเท่ากันเมื่อไม่พบชื่อผู้ใช้ (กันเดาว่ารหัสไหนมีอยู่)
- CSRF: คำขอแก้ข้อมูลต้องมี header `X-CSIS` และ Origin ในรายการที่อนุญาต (สคริปต์ทดสอบที่ไม่มี header ถูกปฏิเสธจริง)
- นักเรียนเรียก API ของเจ้าหน้าที่/ผู้ดูแล 12 จุด → 403 ทั้งหมด (รวมสร้างผู้ใช้ SUPER_ADMIN, ประกาศเกรด, เลื่อนชั้น, อนุมัติจบ)
- ครูเปิด/แก้เกรดวิชาของครูคนอื่น → 404; ครูเรียก API งานวัดผล → 403; แก้เกรดหลังส่ง → 409; คะแนนนอกช่วง/นักเรียนนอกวิชา → 400
- กดอนุมัติพร้อมกัน 2 ครั้ง → สำเร็จ 1 ครั้ง (ล็อกแถว); นักเรียนเห็นเกรดเฉพาะหลังประกาศ
- อัปโหลด Excel: ตรวจชนิดไฟล์จากเนื้อไฟล์, จำกัด 5 MB, อ่านค่าไม่รันสูตร, ไฟล์ของครูไม่บันทึกอะไรจนกว่าจะกดบันทึก
- คำร้อง: ดูได้เฉพาะเจ้าของ/ผู้พิจารณา/ที่ปรึกษา/หัวหน้าสาขา (ตรวจโค้ด — ยังไม่มีข้อมูลคำร้องของนักเรียนคนอื่นให้ทดสอบจริง: NOT TESTED แบบ dynamic)
- Error ไม่เปิดเผยรายละเอียดภายใน; มี audit log ทุกการเปลี่ยนสถานะเกรด เลื่อนชั้น อนุมัติจบ

ผลทดสอบอัตโนมัติ (48/48 PASS):
- ไม่ล็อกอิน → 401, นักเรียน/ครู → 403 ทุก endpoint ใหม่ (8 เส้นทาง × 3 กลุ่ม)
- งานทะเบียนดูสถิตินักเรียน/คำร้องได้ แต่ข้อมูลครู แม่แบบ และการนำเข้าครู → 403 · ประวัตินำเข้าของงานทะเบียนไม่มีรายการประเภทครู
- CSRF: ไม่มี `X-CSIS` หรือ Origin แปลกปลอม → 403
- ตรวจข้อมูลเข้า (zod): อีเมลผิด สถานะไม่รู้จัก uuid ปลอม (รวมสตริง SQL) → 400 · id ที่เป็นนักเรียน → 404
- Mass assignment: ส่ง `userId`/`roles`/`status` ปนมา → ไม่มีผล (บัญชียังระงับ ไม่ได้ SUPER_ADMIN)
- ค้นหาด้วย `' OR 1=1 --`, `%_\`, `<script>` → 200 และไม่คืนข้อมูลทั้งตาราง (Prisma ส่งเป็นพารามิเตอร์; SQL ดิบตัวเดียวเป็น tagged template)
- ผลลัพธ์ไม่มี `passwordHash`
- อัปโหลดไฟล์ปลอม (.xlsx ที่เป็นสคริปต์) และ .exe → 400 จากการตรวจเนื้อไฟล์ · ไฟล์ 6 MB → 413 · ไม่มีงานนำเข้าถูกสร้าง
- นำเข้าไฟล์เดิมซ้ำ → ระบบเตือนก่อนบันทึก · แถวรหัสซ้ำในไฟล์ → ผิดพลาด ไม่นำเข้า
- ชุดทดสอบ API เดิม 33/33 PASS · unit test 104/104 PASS · `npm audit` ไม่เปลี่ยนจากเดิม
